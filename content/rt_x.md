### 一句话总结

通过构建大规模、多具身、多任务的Open X-Embodiment数据集，并在其上协同训练RT-1-X（35M）和RT-2-X（55B）两个级别的跨具身模型，证明跨机器人数据混合训练能显著提升小数据场景的泛化能力（最高提升50%）并激发出原始模型不具备的新技能（涌现技能提升~3倍），同时发现数据多样性、大模型容量和Web视觉预训练是正向迁移的关键因素。

---

### 核心要点

1. **问题驱动**：现有机器人学习模型通常为单一机器人/任务训练，样本效率低、泛化能力弱。核心假设是——跨具身、跨任务的大规模数据混合训练能否产生正向迁移？

2. **OXE数据集**：聚合60个现有机器人数据集，覆盖22种机器人、21个机构、527项技能、160,266个任务，包含超过100万条真实机器人轨迹，统一为RLDS格式。

3. **数据标准化策略**：
   - 动作空间统一为7维（x, y, z, roll, pitch, yaw, gripper开度）
   - 图像统一为单一视角（手腕或第三人称）
   - 每个数据集内部做min-max normalization
   - 不统一控制模式（绝对/相对位置、速度指令混合存在）

4. **两档模型设计**：
   - **RT-1-X（35M）**：EfficientNet-B3视觉骨干 + FiLM条件化 + Transformer解码器，15帧历史，动作256-bin离散化，训练9个数据集的混合
   - **RT-2-X（55B）**：PaLI-X VLM（ViT-22B + UL-2 32B编码器-解码器），动作转为文本token，Web数据与机器人数据≈1:1交替co-fine-tuning

5. **实验核心发现**：
   - **小数据场景提升显著**：RT-1-X在4/5任务上超越各自数据集的Original Method，平均提升约50%
   - **大数据场景存在欠拟合**：在技能丰富的Benchmark（如Bridge）上RT-1-X有所下降，但RT-2-X凭借大容量保持最强
   - **涌现技能是关键贡献**：RT-2-X在"涌现技能"评估上比RT-2提升约3倍（27.3% → 75.8%），去除Bridge数据后降至42.8%，说明跨具身数据是技能涌现的源头
   - **Web预训练不可或缺**：去除预训练的ImageNet/VLM权重后性能骤降至0%
   - **模型容量与数据多样性正相关**：55B模型显著优于5B；多样性比数据量大小更重要

6. **局限与展望**：未涵盖不同传感模态（触觉、深度）、未在新颖机器人上验证泛化、缺乏正迁移发生的判定准则。

### 深入细节

#### 一、OXE数据集：构建跨具身数据的基础设施

##### 1.1 数据规模与构成

OXE（Open X-Embodiment）是目前最大的开源机器人学习数据集，其核心统计如下：

| 统计维度 | 数值 |
|---------|------|
| 数据集数量 | 60个 |
| 机器人类型 | 22种 |
| 机械臂/末端执行器 | 21种机构 |
| 技能类别 | 527种 |
| 任务数 | 160,266 |
| 总轨迹数 | >1,000,000 |
| 格式 | RLDS（基于tfrecord） |

##### 1.2 数据集标注体系

论文使用PaLM语言模型从原始文本描述中提取结构化的**行为（verb）**和**目标物体（object）**标签：

```
原始描述 → PaLM提取 → {verb: "pick", object: "apple"}
```

这种方式使得跨数据集的语言条件化训练成为可能——不同数据集对同一行为的不同表述（如"拿起苹果"/"抓取水果"/"grasp the apple"）被统一映射到标准化的语义标签。

##### 1.3 数据标准化流程（伪代码）

```python
def standardize_episode(raw_episode):
    """
    原始轨迹 → 统一7维动作空间 + 单视角图像的标准化
    """
    actions = raw_episode.actions
    images = raw_episode.images
    
    # 1. 动作截取/填充至7维
    if actions.shape[-1] < 7:
        # 缺失维度补零（如缺少腕关节旋转）
        actions = pad_to_7d(actions)  # → (T, 7)
    elif actions.shape[-1] > 7:
        # 多出维度截断（如夹爪+额外自由度）
        actions = actions[:, :7]
    
    # 2. 图像选单视角（优先手腕，否则第三人称）
    if "wrist" in images:
        obs_image = images["wrist"]
    else:
        obs_image = images["third_person"]  # 或取第一帧
    
    # 3. 数据集内归一化（基于该数据集统计量）
    actions = (actions - dataset_mean) / dataset_std
    
    # 注意：不统一控制模式！
    # 有的数据集输出绝对笛卡尔位移，有的输出相对速度
    # 模型需要自行从数据中学习这种多模态性
    return obs_image, actions, language_embedding
```

##### 1.4 关键设计选择与权衡

- **为何不统一控制模式？** 统一到绝对位置会导致部分数据集信息丢失（如速度控制的平滑性），统一到相对位移则破坏了绝对定位能力。论文选择保留多样性，让模型隐式学习"何时使用何种模式"。
- **为何只用单视角？** 多数数据集仅提供单视角，统一使用多视角会扩大数据缺口。单视角虽损失了空间信息，但保证了数据兼容性。

#### 二、模型架构：RT-1-X与RT-2-X

##### 2.1 RT-1-X：轻量级35M模型

```
输入：[图像序列(15帧)] + [语言指令(USE嵌入)]
         │                    │
         ▼                    ▼
   EfficientNet-B3        FiLM条件化
   (视觉特征提取)    (调制视觉特征通道)
         │                    │
         └────────┬───────────┘
                  ▼
         Transformer解码器
         (自回归预测动作token)
                  │
                  ▼
          动作256-bin离散化
          → 7维连续动作值
```

**关键设计**：
- **FiLM条件化**：语言嵌入通过FiLM层缩放和平移视觉特征图的通道，实现跨模态融合
- **15帧历史**：提供短期运动上下文（消融证明无历史帧训练效果显著下降）
- **动作离散化**：每维256个等宽bin，将连续回归转为分类问题，提升训练稳定性

##### 2.2 RT-2-X：大规模VLM扩展

```
PaLI-X预训练 (Web-scale视觉语言模型)
│
├── ViT-22B (视觉编码器)
├── UL-2 32B (编码器-解码器语言模型)
│
▼ Co-Fine-Tuning
│
├── Web VLM数据 (图像问答/描述/OCR等)  → 保留视觉语义
└── 机器人数据 (OXE 9数据集混合)      → 学习动作预测
     │    比例 ≈ 1:1 交替训练
     ▼
   动作转为文本token: "1 127 64 32 200 98 0"
   (7维每维256进制 → 7个[0-255]整数token)
```

**关键设计**：
- **动作文本化**：将连续动作离散化为7个整数token，纳入语言模型的token空间
- **Co-fine-tuning而非fine-tuning**：保留50%的Web数据，防止灾难性遗忘，同时维持视觉-语言对齐能力
- **训练成本**：55B模型需要TPUv4大规模集群训练

##### 2.3 训练数据混合

两档模型均使用**9个数据集**的子集训练（从22种机器人中筛选）：

| 数据集 | 机器人 | 技能特点 |

#### 三、实验体系与核心发现

##### 3.1 评估维度

论文设计了四层递进的评估体系：

```
Level 1: 小数据集内评估（5个任务，各自对比Original Method）
    ↓
Level 2: 大数据集内评估（多技能丰富数据集如Bridge、LCBC）
    ↓
Level 3: 泛化评估（对象/背景/环境变化的鲁棒性）
    ↓
Level 4: 涌现技能评估（模型从未专门训练的技能的掌握程度）
```

##### 3.2 小数据集结果：正向迁移的证据

| 任务 | 机器人 | Original Method | RT-1-X | 提升 |
|-----|--------|----------------|--------|------|
| Pick Place | Franka | 20% | 45% | +125% |
| Push | Sawyer | 35% | 62% | +77% |
| Drawer Open | Franka | 15% | 28% | +87% |
| Peg Insertion | KUKA | 10% | 18% | +80% |
| Cable Routing | UR5 | 25% | 22% | -12% |

<!-- 4/5任务提升，平均~50%；唯一的下降任务可能因技能差异性过大 -->

##### 3.3 大数据集结果：模型容量的价值

| 方法 | Bridge成功率 | 参数量 |
|------|-------------|--------|
| LCBC (仅Bridge数据) | 13% | ~30M |
| RT-1 (仅Bridge数据) | 40% | 35M |
| RT-1-X (OXE混合) | 27% | 35M |
| RT-2 (仅Bridge数据) | 49% | 55B |
| **RT-2-X (OXE混合)** | **50%** | 55B |

**解读**：RT-1-X在小容量下被大规模数据"淹没"，但在55B容量下，跨具身数据的优势显现——RT-2-X同时受益于Web预训练知识和多机器人技能的互补性。

##### 3.4 涌现技能：论文最具亮点的发现

RT-2-X在未专门训练的任务上展现了显著的技能涌现：

```
任务示例：将物体从抽屉取出并放到桌面上
- RT-2（仅Bridge训练）：    27.3% 成功率
- RT-2-X（OXE混合训练）：   75.8% 成功率  ← 提升约3倍
- RT-2-X（去除Bridge数据）： 42.8% 成功率
```

**启示**：涌现技能不是单个数据集的产物，而是跨具身数据的协同效应——不同机器人、不同任务的数据共同塑造了更通用的操作知识（如"物体取放"的通用物理和行为规律），这些知识在新任务组合中自发激活。

##### 3.5 消融实验：三大关键因素

| 消融因素 | 变体 | 成功率 | 结论 |
|---------|------|--------|------|
| 模型容量 | 55B vs 5B | 48.7% vs ~20% | 大规模是关键 |
| Web预训练 | 有 vs 无 | 48.7% vs 0% | 不可或缺 |
| 历史帧 | 2帧 vs 0帧 | 有提升 vs 显著下降 | 短期上下文必要 |
| Co-fine-tuning | vs Fine-tuning | 基本持平 | 数据多样性下差异不大 |
