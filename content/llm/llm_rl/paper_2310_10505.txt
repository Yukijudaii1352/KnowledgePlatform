Abstract
Alignment is crucial for training large language models. The predominant strategy is Reinforcement Learning from Human Feedback (RLHF), with Proximal Policy Optimization (PPO) as the de-facto algorithm. Yet, PPO is known to struggle with computational inefficiency, a challenge that this paper aims to address. We identify three important properties of RLHF tasks: fast simulation, deterministic transitions, and trajectory-level rewards, which are
not
leveraged in PPO. Based on these properties, we develop ReMax, a new algorithm tailored for RLHF. The design of ReMax builds on the celebrated algorithm REINFORCE but is enhanced with a new variance-reduction technique.
ReMax offers threefold advantages over PPO: first, it is simple to implement with just 6 lines of code. It further eliminates more than 4 hyper-parameters in PPO, which are laborious to tune. Second, ReMax reduces memory usage by about 50%. To illustrate, PPO runs out of memory when fine-tuning a Llama2-7B model on A100-80GB GPUs, whereas ReMax can support the training. Even though memory-efficient techniques (e.g., ZeRO and offload) are employed for PPO to afford training, ReMax can utilize a larger batch size to increase throughput. Third, in terms of wall-clock time, PPO is about twice as slow as ReMax per iteration. Importantly, these improvements do not sacrifice task performance. We hypothesize that these advantages can be maintained in larger-scale models.

Introduction
Alignment is crucial for instructing Large Language Models (LLMs) to operate by human values. There are two approaches to do this: supervised learning and Reinforcement Learning from Human Feedback (RLHF)
(Stiennon et al.,
2020
; Ouyang et al.,
2022
; Bai et al.,
2022b
,
a
)
. The former approach relies on large amount of pre-prepared human-annotated data, so practitioners have to decide exactly how LLMs should behave upfront, which could be laborious. In contrast, the latter approach RLHF does not need to define everything beforehand. Briefly speaking, RLHF reformulates the text generation task into a sequential decision-making problem and applies Reinforcement Learning (RL) algorithms to solve it. The effectiveness of RLHF is highlighted in the GPT-4 technical report
(OpenAI,
2023
)
.
Despite its notable success, the wide application of RLHF is hindered by its heavy computation burden
(Yao et al.,
2023
)
. To get a better sense, we recap that RLHF unfolds in three principal steps:
•
Step 1: supervised fine-tuning of an LLM is carried out to pinpoint a promising starting position.
•
Step 2: a reward model is learned from human preference data.
•
Step 3: an LLM is fine-tuned on new prompt datasets utilizing an RL algorithm.
The hardest part is the third step, where the LLM has to come up with its own responses and make them better to get high reward scores. For instance, as reported by the DeepSpeed team, while working on an OPT-13B model
(Zhang et al.,
2022
)
with RLHF, the duration expended on the third RL step soared to 10.8 hours, quadrupling the cumulative time of about 2.5 hours spent on the preceding steps; refer to
(Yao et al.,
2023
, Table 4)
. Moreover, according to our observation, the RL step requires more than
2
×
2\times
the GPU memory compared with the first two steps, which hinders the scale-up when computation resources are limited. Motivated by the above observations, this paper works on the third step of RLHF to make it easier and less computationally expensive.
Figure 1
:
Comparison between the building blocks of PPO and those of ReMax. ReMax keeps the reference model (for calculating KL penalty) and removes all the components related to the value model in PPO.
What is the computational bottleneck in the third step of RLHF? We find the overhead is due to the RL algorithm, Proximal Policy Optimization (PPO)
(Schulman et al.,
2017
)
. Specifically, a key component of PPO, the
value model
—which is a neural network trained to estimate gradients—incurs significant computational overhead. To align LLMs with human preferences, the value model typically matches the LLM in size
(Dubois et al.,
2023
; Yao et al.,
2023
)
, which doubles the storage. Furthermore, training the value model requires storing its gradients, activations, and optimizer states, all of which increase computational burden. Researchers have attempted to address this issue by using gradient checkpointing
(Sohoni et al.,
2019
)
, Zero Redundancy Optimizer (ZeRO)
(Rajbhandari et al.,
2020
)
, the offload technique
(Ren et al.,
2021
)
, and a hybrid training engine
(Yao et al.,
2023
)
. However, these techniques results in slow computation, and even with these techniques, the heavy GPU memory consumption of PPO remains an issue.
Is it possible to design a better algorithm for RLHF tasks, hopefully without the value model? We find the answer is yes.

In comparison to PPO for RLHF, ReMax has the following advantages:
•
(A1) Simplicity:
ReMax is very simple (with 6 lines of code to implement) and removes more than 4 hyper-parameters in PPO (e.g., importance sampling clipping, GAE coefficient, value model learning rate, and off-policy training epochs), which are laborious to tune
(Engstrom et al.,
2020
; Zheng et al.,
2023
)
. This is significant as hyper-parameter tuning is expensive for LLMs.
•
(A2) Memory Efficiency:
ReMax can reduce GPU memory usage by about 50% in principle. This enhancement yields to two main benefits. First, ReMax is capable of conducting training within limited GPU resources whereas PPO might run out-of-memory. Second, the memory savings by ReMax can be allocated for larger batch sizes, thereby increasing throughput.
•
(A3) Computation Efficiency:
ReMax offers a reduction in wall-clock time per iteration by eliminating the need to train a value model. This can significantly speed up the entire training process of RLHF. According to our calculation, when the generation time is much smaller than the backpropagation time (a condition usually true for LLMs), PPO runs twice slower than ReMax.
•
(A4) Effectiveness:
Regarding task-specific performance, ReMax is on par with PPO, and at times, even outperforms it (possibly due to the ease of hyper-parameter tuning with ReMax).
To demonstrate the practical impact of the above advantages, we conducted experiments aligning the famous Llama2-7B
(Touvron et al.,
2023
)
model.
With regards to
A2
, ReMax supports training on A100-80GB GPUs without memory-efficient techniques, whereas PPO runs out-of-memory in the same setting. Even when PPO manages training Llama2-7B by using techniques like ZeRO and offload, ReMax still outperforms by enabling the use of 1.3
×
\times
larger batch sizes. Regarding
A3
, ReMax offers a 2.1
×
\times
training speed-up thanks to larger batch sizes and fewer computations. For
A4
, in evaluating response quality using the AlpacaEval
(Li et al.,
2023
)
, with judgments rendered by GPT-4, ReMax achieves a win rate of 63.60% over PPO.

3.3
PPO is not the Best Fit for RLHF
For RLHF tasks, we find that the value model employed in PPO brings a substantial computational burden. This is primarily due to two factors. First, the value model usually shares a similar scale with the language model. Second, the value model’s training requires resources for gradients, activations, and optimizer states. As such, a trainable value (or language) model typically requires more than 4 times the GPU memory during training compared with inference. As a result, roughly 50% of GPU memory usage in PPO is allocated to value model learning, with the remaining portion being dominated by the language model learning. Thus, reducing the computational load imposed by the value model is essential.
In pursuit of this objective, we first revisit the motivation behind introducing a value model in PPO. There are two primary purposes. The first is to improve sample efficiency: for MDPs with
stochastic
transitions and rewards, PPO utilizes the value model to predict the expected long-term return, preventing the wastage of data from past experiences
(Cai et al.,
2020
)
. The second purpose is to enhance computational efficiency: a value model provides an
approximate
estimation of long-term returns, without the need for full trajectory rollouts and evaluations
(Silver et al.,
2016
)
.

6
Conclusion
In this paper, we introduce a new method called ReMax, which offers several advantages, including simple implementation, reduced memory usage, fewer hyper-parameters, accelerated training speed, and better task performance compared with the prevalent practice of using PPO. Overall, ReMax makes RLHF easier and cheaper to use for LLMs.
We acknowledge that ReMax does not address all challenges. Issues like reward hacking
(Skalse et al.,
2022
)
and mis-alignment
(Pang et al.,
2023
)
require careful data collection and the design of reward learning objectives. Nevertheless, an efficient reward maximization method like ReMax aids in quickly identifying issues in RLHF and LLMs.

Appendix C
Experiment Details
We made several changes to the RLHF process when using the DeepSpeed-Chat framework
[Yao et al.,
2023
]
. Here are the key differences:
•
Data Processing:
We adjusted how we handle padding tokens. Instead of using the token of
<|endoftext|>
as padding, we set it to be the end-of-sequence (EOS) token. This change ensures that our models stop generating properly.
•
Supervised Fine-tuning:
We modified the fine-tuning process by focusing on the fine-tuning loss, excluding the next-token-prediction loss for prompt parts.
•
Reward Learning:
We changed how we calculate the classification loss. Instead of considering all hidden states, we only use the last hidden state. This adjustment is based on the PTL theory.
•

In this section, we conduct an experiment on a small model GPT-2 (with 137M parameters). Our goal is to show that the proposed reward maximization algorithm can also be used in the setting beyond RLHF. In this experiment, rather than directly learning from human preference data, the reward model is a sentiment classifier
[Sanh et al.,

, which gives sentiment scores indicating how positive a given text is.
Following

The input of the model is a partial movie review text, with a maximum of 64 tokens. The objective of the model is to generate an additional 48 tokens to complete the review while ensuring the output maintains a positive sentiment and fluency. We use the official implementation at
