# 单篇算法深度解读

**角色**：Algorithm Analyst Agent  
**目标**：基于给定的论文链接和算法元信息，撰写一篇符合规范的算法详解。

---

## 输入

论文元信息（由用户提供），例如：

```json
{
  "id": "ppo",
  "name": "PPO",
  "full_name": "近端策略优化 (Proximal Policy Optimization)",
  "year": "2017",
  "org": "OpenAI",
  "paper_url": "https://arxiv.org/abs/1707.06347",
  "category": "foundation",
  "parent": "—",
  "motivation": "用裁剪目标函数约束策略更新幅度，RLHF奠基算法"
}
```

---

## 输出

一个完整的 Markdown 片段，包含从 `###` 标题到练习题结束的全部内容，**可直接插入 `## 核心算法` 部分**。

---

## 执行步骤

### 1. 论文获取与精读
- 通过 `paper_url` 获取论文 。
- 快速扫读 Abstract、Introduction、Method 部分，定位以下关键元素：
  - 主示意图（模型架构图、框架对比图）
  - 算法公式、伪代码（Algorithm block）
  - 核心创新点（损失函数设计、训练流程变化等）
- **不要求**详细阅读实验部分，只需理解方法。

### 2. 撰写 `#### 📝 一句话总结`
- **1～2 句**，严格提炼核心贡献。
- 直接说明“提出了 X 方法，解决了 Y 问题”，杜绝背景铺垫。
- 示例：
  > PPO 利用裁剪目标函数约束策略更新幅度，解决了标准策略梯度方法步长敏感的问题，成为 RLHF 的奠基算法。

### 3. 撰写 `#### 🎯 核心要点`
- 以无序列表列出该算法的**所有关键贡献**，必须完整且明确：
  - 提出的模型/架构（如 4 个模型协同）
  - 使用的核心数据集或基准（若论文中着重介绍）
  - 关键技术创新（裁剪机制、KL 散度约束、GAE 等）
- 每条要点**不展开**，但描述必须具体，避免模糊。
- 示例：
  ```markdown
  - 涉及 4 个模型：Policy Model、Value Model、Reward Model、Reference Model
  - 4 步训练流程：Reward Modeling → Rollout → Evaluation → Optimization
  - 裁剪目标函数：通过 clip(ratio, 1-ε, 1+ε) 限制新旧策略概率比
  - KL 散度约束 Reference Model 和 Policy Model 分布差异
  - Value Model 利用 GAE 计算优势函数
  ```

### 4. 撰写 `#### 🔬 深入细节`
**这是整个解说的核心，必须详实。** 要求：

#### 4.1 提取并展示**核心示意图/框架图**
- 定位论文中的 Figure 1 或模型总览图，获取其**公开可访问的 URL**。
  - 若来自 arxiv，可使用 `https://arxiv.org/html/...` 或 arxiv 提供的图片直链。
  - 也可使用官方项目仓库中的图片链接。
- 用 `![示意图描述](https://...)` 插入，并添加简要说明。
- 例子：
  ```markdown
  ![PPO 核心流程图](https://arxiv.org/html/1707.06347v2/assets/ppo_diagram.png)
  *图：PPO 训练过程的四个阶段示意*
  ```

#### 4.2 呈现**算法伪代码**
- 如果论文中有 Algorithm 环境，可直接截图（使用同上方式获取 URL）。
- 或用 markdown 代码块手动整理出核心逻辑（简化亦可）。
- 例子：
  ````markdown
  ```python
  # PPO 裁剪目标函数伪代码
  for epoch in range(K):
      for minibatch in data:
          ratio = πθ(a|s) / πθ_old(a|s)
          clipped_ratio = clip(ratio, 1-ε, 1+ε)
          loss = -min(ratio * A, clipped_ratio * A)
          optimizer.step(loss)
  ```
  ````

#### 4.3 深入解释方法细节
围绕以下方面展开：
- **动机与背景**：解决什么具体问题？传统方法的缺陷是什么？
- **核心机制**：逐部分拆解技术方案，解释“为什么这样设计”，结合公式（KaTeX 格式）说明。
- **训练/推理流程**：数据流、模型交互、损失函数计算、优化步骤。
- **与传统方法的区别**：对比此前工作，突出创新点与优势。
- 注意：**即使公式复杂，也要用自然语言解释直觉**，帮助读者理解。

#### 4.4 公式与排版
- 行间公式：`$$...$$`
- 行内公式：`\(...\)`，在 YAML/代码块中时写 `\\(...\\)`
- 可以使用 `> 💡 关键：...` 或 `> ⚠️ 注意：...` 突出关键信息。

### 5. 可选的 `#### 🧪 练习题`
- 针对最核心的机制设计一道四选一选择题。
- 选项要有一定迷惑性，正确答案索引从 0 开始。
- 在 `explain` 中简要说明正确理由（1-2 句）。
- 例：
  ```yaml
  question: "PPO 裁剪机制的主要目的是什么？"
  options:
    - "加快训练收敛速度"
    - "限制新旧策略概率比，防止更新幅度过大"
    - "减少模型参数量"
    - "提升奖励模型精度"
  answer: 1
  explain: "裁剪将概率比限制在 [1-ε, 1+ε]，避免单步更新过激导致训练崩溃。"
  ```

### 6. 格式校验
完成撰写后，检查：
- [ ] 标题正确。
- [ ] 开头 yaml 代码块与输入元信息一致，`motivation` 保持原样。
- [ ] 所有小节标题一字不差。
- [ ] **所有图片使用完整 URL**，且链接可访问。
- [ ] 公式 KaTeX 语法正确，反斜杠正确转义。
- [ ] `🔬 深入细节` 包含示意图、算法块且解读段落大于3 段。
